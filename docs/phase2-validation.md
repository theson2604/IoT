## Preservation and coordinated firmware change

All tracked firmware files except lib/Energy/Runtime.h are byte-identical to HEAD:
board JSON, pin variant, PlatformIO configuration, Radio, INA219 driver, role apps,
wire codec, legacy Modbus and settings are preserved. Runtime.h adds only MQTT
schema_version=1, device_id=node01 and sender_uptime_ms from the existing sensor
frame uptime. Original metric names/units and ESP-NOW bytes stay unchanged.
Energy tests add assertions for these metadata fields; Modbus tests and the
existing C++ test runner are unchanged. Older MQTT telemetry is accepted with
unknown/null uptime. Previous gateway scaffold entrypoint remains usable as a
shim to the new application. Firmware documents/history remain available.

## Manual setup and Phase 3 readiness

Follow gateway-setup.md: install/start loopback Mosquitto, copy ignored .env,
start Gateway and one Simulator, then run RUN_MQTT_INTEGRATION=1 on a dedicated
broker. No physical Collector may share node01 topics with the Simulator.
Hardware migration requires actual STA MACs, AP channel, verified INA shunt/wiring,
PC LAN broker address and a deliberate authenticated LAN listener/firewall policy.
Do not expose the unauthenticated loopback API or anonymous development broker.

A stable normalized REST/SQLite/MQTT boundary now exists for a future CoreIOT
adapter. Phase 3 implementation should follow real-broker end-to-end validation
and physical bring-up; this is not a production/hardware readiness certification.
Known limits: one node pair/process, QoS0/best-effort telemetry, finite duplicate
windows, no boot nonce, no TLS, volatile device energy, wall-clock timeout
sensitivity, float energy conversion precision, no cloud/AI/dashboard features.
Pending commands are never replayed after restart; timeout does not prove a
command was not executed. Public-ID dedup history is bounded by retention.
